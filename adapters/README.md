# HomePanel 原生适配包

0.4.0 首轮实现。适配包是只含数据的 JSON，用于安排当前设备 SPEC 中已有属性的顺序和分组。它不运行 JavaScript，不定义云端接口、权限、属性值、单位换算或固件操作。它与米家手机设备插件是两种不同格式。

## 普通用户怎么使用

内置的插座、灯具、空调、温湿度传感器和风扇面板随 EXE 提供。打开设备时按公开规格匹配，不需要额外下载安装。设备详情的“信息 → 设备面板”显示当前使用的适配包；在“设置 → 设备面板”关闭“使用专用面板”即可回到基础布局。

导入别人提供的 HomePanel JSON 适配包：在“设置 → 设备面板 → 导入本机适配包”点击“选择并导入适配包”，选择文件即可。适配包保存在当前 Windows 用户配置目录下的 `io.github.meowcoa.homepanel/adapters/` 中，重启后仍生效。拒绝相同或更旧版本；无效文件保留已有面板。当前没有线上目录或自动更新服务。

`examples/chuangmi-plug-212a01.json` 是一个可导入的精确型号示例，使用公开 MIoT 属性名称独立编排，不含官方图片/代码。只有型号完全匹配才生效；该示例未获得真实硬件兼容认证。它也不会把别的第三方插座识别为这个型号。

## 匹配与降级规则

- 精确型号优先于完整 SPEC URN，完整 URN 优先于公开标准设备类型；不按用户修改的设备名称匹配，不支持通配符。
- 相同优先级匹配到多个不同包时使用基础面板，避免随机选择。
- 只绑定真实 SPEC 中已有且目标不重复的属性；readings 分组只显示可读且不可写属性，controls 分组只显示可写属性。
- 设置与控制仍遵循现有属性分类；指示灯不会因适配包被当成主电源。未匹配或未编排的属性继续通过基础控件显示。
- 属性读写继续使用现有通信校验、状态来源、拖动提交、结果回读与错误提示。适配包不能提供假状态或放宽权限。

## 格式

```json
{
  "schemaVersion": 1,
  "id": "example-outlet",
  "version": 1,
  "name": "示例插座面板",
  "license": "MIT",
  "source": "Author and protocol reference",
  "matches": { "models": ["example.plug.v1"] },
  "sections": [
    {
      "page": "controls",
      "title": "用电读数",
      "style": "readings",
      "properties": [{ "key": "electric-power" }, { "key": "voltage" }]
    }
  ]
}
```

`matches` 支持 `models`、`specUrns`、`deviceTypes` 数组；每个数组内是精确字符串，三个数组按“任一匹配”处理，命中最具体的条件作为优先级。属性选择器可加 `serviceKey` 精确限制服务。`page` 为 `controls` / `settings`，`style` 为 `controls` / `readings`。读数固定两列；高度和窗口尺寸由本机绘制代码控制。

限制：单包 64 KiB、最多 16 个分组、每组最多 32 个选择器；本机目录最多载入 32 个 JSON。未知字段、脚本字段、路径穿越标识、通配型号、不支持版本会被拒绝。

## 与手机插件结合的当前边界

设置里可选择本机 ZIP / mpkg 插件包进行离线格式与依赖检测，检查完成后继续使用原生面板。检测不执行包、不访问账号、不把官方包导入 HomePanel，也不验证其签名链。它只是兼容入口检查，尚未形成能运行官方插件的 Windows RN 宿主。

要增加远程自动更新，需要先建立有明确维护者和可信发布链的包目录，再接入版本、完整性和签名验证。当前未上传 GitHub，也没有把一个未发布或可变的 URL 冒充更新源。
