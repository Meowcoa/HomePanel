# HomePanel

HomePanel 是一个面向 Windows 的原生米家设备控制器：常驻系统托盘，点击即可打开设备面板，支持家庭/房间筛选、设备状态、开关控制和详情设置。界面使用 Rust 与 `eframe/egui` 绘制，不依赖浏览器、Node.js、Rust 或 WebView2 才能运行。

当前发布版本是 **0.4.11**。它重点完善了音箱状态读取、插件下载记录、插件校验与 Windows 宿主入口，同时保留轻量的原生控制面板。默认界面采用冷白玻璃风格，支持通透玻璃、毛玻璃和纯色回退；窗口尺寸固定，兼顾 Windows DPI、减少动画和托盘操作。

## 下载

从 [Releases](https://github.com/Meowcoa/HomePanel/releases) 下载最新 Windows x64 安装包。安装包会自动处理同一安装目录中的旧版 HomePanel，保留本机账号设置；安装、升级和卸载都对占用文件做检查。

发布附件同时提供 SHA-256 校验文件。安装后直接从开始菜单启动，也可以运行安装目录中的 `HomePanel.exe`。首次启动需要使用米家扫码登录，账号会话只保存在当前 Windows 用户目录中。

## 主要功能

- 系统托盘驻留，左键开合面板，右键进入设置或退出。
- 家庭与房间筛选、设备搜索、收藏、隐藏和恢复设备。
- 设备卡片直接开关，详情页按公开 MIoT SPEC 显示开关、读数、滑杆、模式和设备专属属性。
- 状态优先直读设备；读取失败时明确显示待确认或缓存状态，不把旧数据伪装成实时状态。
- Xiaomi 智能音箱的播放状态、歌曲、音量、循环和进度读取与受限控制；未确认的修改会保留提示并再次读取。
- 可按设备型号查询和下载米家插件，查看“已下载插件”列表，并在本机完成包摘要、证书链和运行文件检查。
- 可选 Windows RNW 插件宿主按需启动；插件与账号会话隔离，关闭插件后释放宿主进程。

## 当前边界

HomePanel 不是小米官方客户端，也不承诺全部米家设备或官方插件兼容。原生控制面板支持范围取决于设备公开 SPEC 和当前服务区；插件宿主只开放精确型号、版本、SDK 和完整 SHA-256 均命中的候选包。

当前插件准备矩阵包含 `xiaomi.wifispeaker.l05c` v25、`chuangmi.plug.212a01` v31 与 SDK 10116。插座和音箱的 Windows 宿主挂载、读取、轮询和隔离测试已通过，但真实 Windows 像素、官方按钮交互和所有第三方专属功能仍需逐型号验收。插件下载完成不等于官方界面已经兼容。

官方插件、SDK、APK、用户导入的验签根、图片和账号数据不会进入 GitHub 源码或安装包。程序不会替用户写入米家隐私同意记录，也不会发送未经核实的设备删除、绑定、解绑或 OTA 请求。详细范围见 [插件下载说明](PLUGIN_DOWNLOAD.md)、[插件兼容性](PLUGIN_COMPATIBILITY.md) 和 [米家接口覆盖](MIJIA_API_COVERAGE.md)。

以下保留 0.4.10 及以前的功能和验证记录。其中插件尚未下载、未验签或仅支持 plain bundle 等描述对应当时版本；0.4.11 的当前边界以上文及 [插件下载说明](PLUGIN_DOWNLOAD.md) 为准。

0.4.9 音箱控制与状态恢复改动保留。音箱主“控制”页连接小爱后，歌曲、播放、音量统一走小爱通道；主按钮随状态显示暂停、继续播放或播放音乐。修正逐设备 V3 协议标记，读取 `capabilities.ai_protocol_3_0` 并发送 `isV3Protocol=1/0`，不再读取不存在的顶层 bool。

播放、睡眠、蓝牙独立保存读取时间和错误。操作未确认时保留最后读到的数据、标为旧状态并自动恢复读取；一个接口失败不再清空整页或禁用其他已读功能。进度在两次查询之间按播放时间平滑前进，拖动和待确认数值保持稳定。重登、旧响应、跨页忙碌和断网草稿也已修正。

通用播放、音量、循环和进度使用独立的小爱播放器契约：要求同账号下 `miotDID` 唯一绑定、当前型号属于 `xiaomi.wifispeaker.*`、公开 speaker SPEC 已加载，并读到操作所需的有效状态。通用播放器不再受硬件屏幕白名单限制，也不猜测型号后缀等于 hardware；第三方音箱继续使用原有公开规格通道。硬件信息仅用于相应快捷功能的限制：屏幕类型未知或带屏时不开放蓝牙快捷开关；睡眠还须声明夜间能力，并排除 LX04、T646 和组合音箱。组合播放器的组服务器路由尚未接入，暂不开放其播放、音量、循环和进度写入。

上下首通过同源 audio_id/global_id 确认；无队列时，明确点击“播放音乐”可使用手机固定的启动音乐后备请求，不会因轮询或连接自动播放。音量与循环写入后先等待 3.25 秒再回读，避免过早读取旧状态；未读到对应变化仍显示未确认，不重复发送。安装时继续自动退出目标目录的旧版，保留账号配置。

本轮已对明确授权的真实音箱进行安静的循环切换与恢复：部分目标确认改变，其他目标受理后未读到目标值变化；全部实际写过的目标均经稳定复查确认恢复原值。后者是“修改未确认”，不能写成设备拒绝，也不代表所有型号循环已兼容。真实播放、音量、进度、睡眠和蓝牙修改尚未测试；具体结果以交付目录 verification.json 为准。

保留 V3 设备列表修正：解析 `data.deviceList`，保留按 miotDID 唯一匹配；支持 App 声明的 code/status、data/result 响应别名，拒绝冲突和缺失结果。本地 HTTP 模拟验证已覆盖列表到播放状态的完整读取链路，本轮也已取得真实连接的列表和有效状态字段。读取失败不再误写为“此音源暂未提供”，详情底部刷新同时查询小爱状态；真实修改不能由读取成功推定。

保留扫码后的 STS `clientSign` 会话校验；使用本次授权返回的 nonce/ssecurity，保留 64 位整数精度并正确编码签名。失败提示现在区分授权、回调跳转和服务异常，并显示 HTTP 状态码，不包含账号或回调参数。

修复毛玻璃详情背后显示整块主面板背景：主面板与详情分别使用固定的 460×620、388×540 原生窗口范围，只在打开/关闭详情时一次切换；控件、滑杆、刷新与动画不改变尺寸。关闭 Windows 11 整窗 system backdrop，使用区域裁切的 Acrylic，继续支持通透玻璃和纯色。

Xiaomi 音箱“小爱”页通过独立 `micoapi` 扫码授权获取专用播放状态、歌曲、进度、循环、睡眠及蓝牙信息。公开规格控制继续校验 SPEC；小爱播放器和各快捷功能分别校验协议、设备身份及有效字段，不能用未知屏幕类型推断蓝牙权限。缺失对应状态、会话失效或目标不唯一时不发送修改。用法及边界见 [小爱服务说明](SPEAKER_SERVICE.md)。

原有官方插件集成测试功能保留。原生托盘、设备卡片、玻璃效果和型号适配包继续保留；集成安装包另外安装 Windows RNW 0.79.5 宿主、Windows App SDK 及应用目录内的 VC++ 运行库，不要求用户安装 Node.js、Rust 或 Android 环境。宿主按需启动，关闭/退出账号/退出主程序会结束对应宿主；主程序异常退出时，宿主通过父进程监视收起并退出。

这不是全部米家插件兼容认证。当前只开放本机 `miot.plugin.spec` 1.1.10 plain bundle 候选，并限公开 SPEC 中仅有一个主开关的插座。测试数据的挂载、SDK 读写、回读与轮询已验证；真实设备、官方按钮和最终像素仍待用户安装实测。两个 RAM bundle、Hermes 89 字节码、厂商私有接口、场景/历史/云推送尚未实现。

安装当前 Release 中的 `HomePanel-Setup-0.4.11.exe` 后，在“设置 → 设备面板 → 官方插件 · 集成测试”导入自己合法持有的米家 APK，再在插座详情“信息”页选择“打开插件 · 只读”。确认状态正确后，可选择“打开插件 · 启用控制”；插件点击产生的真实修改继续由 Rust 校验公开 SPEC 并回读确认。不能读取当前值或缺少手机接口时显示失败，不用假成功填充。

导入不会上传 APK。只接受精确 SHA-256 匹配的 SDK、通用插件和资源 ZIP，将两份 JS 与本机光栅图片保存到当前用户 AppData；不提取账号、证书、手机原生库或开发者凭据。SHA 匹配仅用于限定已研究样本，不等于发行签名验证或再分发授权。源码和安装包均不含这些用户文件；插件未知版本会拒绝，继续使用原生面板。没有自动下载源。

原生适配包可独立使用，见 [适配包说明](adapters/README.md)。兼容与验证范围见 [COMPATIBILITY.md](COMPATIBILITY.md)，宿主构建见 [记录](experiments/rnw-host/README.md)。早期 React/Tauri 原型不参与 Rust 构建。

## 安装与控制

0.3.10 同时提供独立的 `HomePanel.exe`：Windows 10/11 x64 用户退出旧版后直接运行即可，不需要 Rust、Python、Node.js、WebView2 或额外安装 Visual C++ 运行库。运行库静态链接，中文字体、界面及默认图形内嵌在 EXE 中；也可使用安装包添加开始菜单与卸载入口。账号会话、个人设置及缓存仍保存在本机 AppData，不打进分发文件。字体采用可再分发的 Noto Sans CJK SC，许可在设置页和 `LICENSES/` 中保留。

窗口和毛玻璃使用一致的 24 逻辑像素圆角裁切，并按 DPI 换算，避免透明角露出背景层。页面和详情内容采用约 200 ms 的淡入与轻微位移，页签胶囊平滑滑动，图标按钮提供轻微按压反馈；窗口尺寸、玻璃背景和控件命中区域保持稳定。系统减少动画开启时即时切换。

0.3.9 的家庭概览可以点击，进入按房间分组的“已开启设备”，直接开关或打开详情；也能切换离线和待确认列表。当前家庭的列表不受首页房间/搜索筛选限制，返回后保留原筛选。在线不等于开启；只统计最近有效的设备开关/播放回报，缓存、失败或超过 45 秒的状态进入待确认。指示灯和音箱闹钟不再参与电源统计，多路设备按任一通道开启计一台，并在详情独立控制各通道。

详情固定分为“控制／设置／信息”：插座开关及功耗读数放在控制页，点动、按键、指示灯、来电状态等集中在设置页，并附解释；信息页显示实际设备类型、型号、房间、读取来源及兼容信息。未知厂商选项保留原值及说明，不猜测含义。第三方插座命名为“热水器”不会改变其协议类型。手机功能接入范围、场景/推送等未完成模块见 [MIJIA_API_COVERAGE.md](MIJIA_API_COVERAGE.md)。

0.3.8 修复通用状态同步：打开详情、手动刷新和后台轮询优先直读设备（`datasource=2`）；缺少或失败的属性才回退到只读云端缓存（`datasource=3`），并明确标注上报时间未知。详情读取成功后间隔约 3 秒轮询；缓存或失败时退至 15 秒，其他设备以 15 秒为最短间隔，最多并行两台后台读取，依次覆盖当前列表全部在线设备。面板隐藏后停止周期轮询，重新打开即安排刷新；在线列表约每 60 秒重新查询。它仍是轮询，不是实时推送。

每项属性独立记录读取时间与来源；缺行、错误设备、重复或失败响应不会继续伪装成当前状态。底栏显示设备回读、云端上报或读取失败；悬停属性可查看来源，写入专用属性显示“仅支持设置”。后台读取不再锁住滑杆和按钮，同设备通信串行，旧结果不能覆盖较新的确认值。写入确认后重读其他属性，播放动作后延迟读取，不重复发送动作。

0.3.7 增加窗口失焦自动收起，已取得焦点后切到其他程序或桌面，经过约 160 ms 缓冲收起；同进程窗口及面板内下拉菜单不触发。音箱使用专用播放状态与控制区，音量、静音保留在常用区，其他属性收进“更多设置”；空音频编号显示“暂无音频”。启用时段改为开始/结束时分秒选择器，按公开 SPEC 的秒格式保存，回读可识别等价的分钟格式。不能把音箱闹钟开关当成设备电源。网络结果返回后会主动重绘，避免多等一次周期刷新。

0.3.6 修复详情滚动时控件越过标题/底栏，以及等待设备确认时后续控件上移 10 像素的问题。滑杆按设备步进绘制，拖动、数值与圆点同步；松手后保持提交值直到确认完成，失败再恢复原值。详情错误与提示使用固定底栏，不遮挡按钮。空调常用控制保留在主页，其余 SPEC 属性仍可从“更多设置”使用；新增原创空调图形。

0.3.5 根据用户提供的米家 Android APK 行为研究修正属性设置兼容性：仅将匹配设备、服务和属性的单项返回码 `0/1` 视为已受理，仍需回读一致才显示成功。控制后只请求目标属性的新值，最多用 8 秒确认，不自动重复写入；发送超时也会尝试回读。状态未确认显示黄色提示，明确拒绝才显示错误。开关、音箱和驱蚊器新增原创矢量图，设备类别优先按公开 MIoT device URN 识别。分析方法与边界见 [APK_ANALYSIS.md](APK_ANALYSIS.md)，真实设备仍待验证。

0.3.4 修复面板隐藏后托盘打开/退出不响应，以及后台阻塞任务拖住进程退出的问题。显式退出会先登记退出意图，再唤醒原生窗口事件处理并关闭；隐藏窗口在退出过程中以最小化且不激活的方式唤醒。程序关闭后，后台运行时清理最多等待 2 秒。设置页右上角新增“退出程序”，保留本机登录状态和设置；“退出当前账号”仍是独立的注销操作。

0.4.7 安装包会自动关闭目标安装目录中的 HomePanel；先请求正常退出，不响应时再核对并结束该进程。本机配置保留，不需要重新绑定设备。

早期 0.3.3 安装器要求先手动退出；0.4.7 安装包已自动处理。文件可写检查仍然保留，占用、权限不足或无法退出时不会忽略错误继续覆盖。卸载保留占用检查，仍需先退出程序。

若仍在 0.3.2 的旧报错窗口中，先从托盘退出程序，再点“重试”；不要点“忽略”。

运行 `HomePanel.exe`，或安装 `HomePanel-Setup-0.4.11.exe` 后从开始菜单启动。首次运行显示扫码登录；之后可以左键点击托盘图标开合面板，右键托盘打开设置或退出。

0.3.2 将详情面板固定为 `388 × 540` 逻辑像素，关闭按钮固定在右上角。调整滑杆、等待回读、切换设备和展开设置时，外框保持相同尺寸。应用比例固定为 100%，同时遵循 Windows 的 DPI 缩放。

温度、湿度和电量使用大字读数；单位显示为 `°C`、`%`、`K`。常用模式直接点选，次要功能在设备“设置”页里。玻璃外观参考 Apple 官方设计指南，桌面背景模糊由 Windows 原生 Acrylic 提供；系统关闭透明效果时使用纯色面板。它不是 Apple Liquid Glass 渲染器。

右上角搜索支持设备名称与房间；所有操作图标和设备插画均由本项目绘制，不依赖符号字体或新增图片包。

卡片上的电源按钮可直接开关设备，点击卡片主体打开详情。右键卡片或点“⋯”可以查看详情、直接开关、收藏、刷新状态，或只在 HomePanel 中隐藏设备；隐藏设备可从设置恢复。

“从米家家庭移除”会改变小米账号中的设备绑定。当前核对过的开源接口没有可验证的移除调用，因此这个菜单项暂不可用；HomePanel 不会把本地隐藏冒充成米家删除，也不会发送未经核实的删除请求。

只有 MIoT SPEC 明确提供且当前账号允许的属性会显示为控制项。只读传感器不显示电源按钮。摄像头画面、AI、小爱接管和自动化引擎不在当前版本范围内。


0.3.2 在“设置 → 外观 → 背景材质”中提供 **通透玻璃 / 毛玻璃 / 纯色**，切换立即生效。通透玻璃保留桌面细节，毛玻璃使用 Windows Desktop Acrylic 模糊背景；系统关闭透明或启用高对比度时回退到纯色。材质由系统合成与静态矢量高光完成，没有新增浏览器、后台动画或图片依赖。

设备详情的只读读数按两列排列，插座优先显示功率、用电量、电流、电压四格。中文服务、属性、动作和枚举优先使用公开 MIoT 中文元数据，并在本机缓存；下载失败不会阻断设备控制，稍后重试。三键模式按服务名称区分，无法确定左右位置时只标注通道号。未提供中文的厂商选项显示“待翻译”，原始说明可悬停查看，不编造含义。

电气单位与倍率仅在显示层转换，不改变设备上报值和写入参数。`chuangmi.plug.212a01` 的公开规格 1–3 中，功率按原始值 × 0.01 显示 W，电流显示 mA，电压显示 V；上报电量按 mWh 转为 Wh，统计周期以设备为准，不能当成累计度数或乘 6 外推一小时。其他型号优先使用其 SPEC 单位，缺失时标注“原始读数 · 单位待确认”。这些规则尚未经过真实设备校验。

## 账号与隐私

- 应用不要求输入小米账号密码。扫码登录使用社区实现的账号会话流程，不是本项目取得的官方 OAuth 应用授权。
- 会话由当前 Windows 用户的 DPAPI 加密，保存在 `%APPDATA%\io.github.meowcoa.homepanel\session.dpapi`。
- HomePanel 不读取米家 App、浏览器或其他程序的登录缓存；没有自建中转服务器或广告。集成版 Microsoft 运行库另按其随附数据条款使用。
- 退出账号只清除 HomePanel 本机保存的会话。卸载程序会保留账号会话和设置；如需清除，可先在程序中退出账号。
- 不要把应用配置目录、私人设备信息或登录二维码发到公开 Issue。日志和错误提示不会输出会话内容。

## 设备图片

源码和安装包不包含未经授权的小米官方设备图片，默认图标由本项目自行绘制。只有确认图片可用于此客户端后，才在“设置 → 设备图片”登记型号、官方 HTTPS 地址和许可依据。图片请求不携带账号凭据，缓存只保存在本机。

## 开发与打包

需要 Rust stable（最低 1.88）、Visual Studio C++ Build Tools 和 Windows SDK。运行程序和构建当前原生版本不需要 Node.js、浏览器或 WebView2。

```powershell
$workspaceRoot = (Get-Location).Path
$env:CARGO_TARGET_DIR = Join-Path $workspaceRoot 'work\cargo-target'
cargo test --locked --manifest-path src-tauri/Cargo.toml
cargo build --locked --release --manifest-path src-tauri/Cargo.toml
```

开发版可以用 `cargo run --manifest-path src-tauri/Cargo.toml -- --demo` 打开明确标注的演示设备；`--demo-detail` 额外展示一台演示设备的详情。演示窗口、单实例保护和配置目录与正式版隔离。演示参数只在 Debug 构建中生效，不会连接、读取或控制真实设备，也不会保存演示设置。Release 构建会忽略这些参数。

Debug 演示中按 `F8` 可以检查黄色“状态待确认”提示，内容明确标为演示；此入口不进入 Release。

`--demo-climate` 打开多控件空调回归面板，演示写入模拟 650 ms 确认延迟，用于检查等待期间的布局和滑杆位置，不访问真实账号。

`--demo-speaker` 打开音箱面板，提供播放状态、控制按钮与时段编辑的合成数据；同样只在 Debug 生效。

Debug `--demo --demo-layout` 用于原生布局检查，保持隔离演示窗口显示以便截取和点选。该模式不做失焦收起验收，也不进入 Release 行为；普通演示和正式程序仍按原有失焦逻辑处理。

正式程序尚未下载或执行米家手机插件，继续使用原生面板。独立 Windows RN 实验已在本机运行 `miot.plugin.spec` 1.1.10 的 plain bundle，补齐旧 SVG、safe-area 和部分 SDK 事件格式；测试插座通过读取、修改、回读及轮询通知。官方按钮、图片资源、真实设备和其他厂商插件仍待验收。实验源码与精确边界见 [宿主记录](experiments/rnw-host/README.md)，闭源样本只留在工作区本机研究目录。

接近手机米家的易用性需要按设备类别/型号逐步做专用面板、核准模式和单位、完善状态同步，并记录真实设备验证。当前已做空调和音箱的首轮整理；音箱的播放状态取设备 SPEC 枚举，无法读取时明确显示不可读。播放动作受理后会请求新状态，“指令已受理”不等于播放已经执行。摄像头、绑定/解绑、OTA 与厂商私有服务仍未实现，不能承诺与手机全功能一致。

生成安装程序需要 NSIS 3.13；它只用于开发打包，不会安装到用户电脑。编译完成后运行：

```powershell
.\scripts\Build-Portable.ps1 -WorkspaceRoot $workspaceRoot
.\scripts\Test-Portable.ps1 -WorkspaceRoot $workspaceRoot
.\scripts\Build-Installer.ps1 -Version 0.4.11 -WorkspaceRoot $workspaceRoot -ReleaseExe (Join-Path $workspaceRoot 'work\HomePanel-release-0.4.11\HomePanel.exe')
```

独立 EXE 和安装包会生成在工作区 `work\HomePanel-release-0.4.11\`。独立版构建显式选择 x86_64 MSVC 目标及 `+crt-static`，并检查 PE 导入表中不存在动态 VC/C 运行库。`Test-Portable.ps1` 在空工作目录、隔离配置和移除开发工具的 PATH 下运行不访问账号的字体自检；它不等于全新 Windows 虚拟机或所有显卡驱动兼容验证。GitHub Actions 上传独立 EXE、安装包及校验值；推送 `v*` 标签时只创建草稿 Release，等待维护者审核后再发布。

生命周期测试需 Windows 图形桌面：先构建 Debug，再运行 `scripts/Test-Lifecycle.ps1 -WorkspaceRoot <工作区路径>`。它通过仅 Debug 可用的 `--demo-lifecycle=` 启动隔离模拟窗口，覆盖显示退出、隐藏退出、隐藏后打开再退出、隐藏后再次启动恢复和阻塞后台任务，不接触真实设备。测试代码及参数不进入 Release 行为；这些桌面用例在本机执行，不作为无图形环境 CI 已通过的证据。

安装器回归测试使用 `Build-Installer.ps1 -TestMode` 生成独立的 `-test.exe`，然后运行 `scripts/Test-Installer.ps1`。测试只在工作区 `work/` 中创建安装目录、测试快捷方式和隔离注册表项；用不连接设备的空白进程模拟程序占用，验证阻止改写、退出后安装、重复升级以及卸载。现有测试注册表项存在时会停止，避免覆盖。CI 只上传正式安装包。

便携工具链仅供本工作区使用，可在 PowerShell 中点载 `.\scripts\Use-LocalToolchain.ps1`。原型目录中的 npm/Vite/Tauri 文件不参与上述流程。
